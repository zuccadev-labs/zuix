zuix is a UI suite built around one standard: design tokens, icons, components, layouts and a documentation
template. The standard is HTML, CSS and tokens. It works with any framework or with none, and it ships a
React binding. A brand reproduces the whole system by changing one file.

I maintain it alone, under the `zuccadev-labs` organization. The detailed documentation is written in
Spanish; this file and the package READMEs are in English.

## The three layers

| Layer | What it is | Depends on |
|---|---|---|
| Contract | `--z-*` tokens, `z-*` classes, state attributes (`data-state`, `data-size`, `aria-*`) and icons | Nothing: CSS and SVG |
| Behavior | `@zuccadev-labs/zuix-zui/dom` and `@zuccadev-labs/zuix-zout/dom`: dialogs, menus, popovers, tabs, panels, form controls | The browser (`<dialog>`, Popover API) |
| Binding | `@zuccadev-labs/zuix-zui` and `@zuccadev-labs/zuix-zout` for React | React 19 |

The markup of every component lives in `zui/html.json` and `zout/html.json`, generated by rendering the
React binding. A binding for another framework only has to produce that markup; the look is never rewritten.

There is no third-party UI library underneath. Dialogs are a native `<dialog>` opened with `showModal()`,
floating layers use the Popover API, and the keyboard and focus logic follows the
[WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/). The same logic drives the React binding
and the framework-free mode.

## Packages

| Package | Folder | What it is | Published |
|---|---|---|---|
| `@zuccadev-labs/zuix` | [`suite/`](./suite/README.md) | Umbrella: installs the four below and re-exports them under subpaths | Yes |
| `@zuccadev-labs/zuix-tokens` | [`tokens/`](./tokens/README.md) | Single source of design values. A brand is one file | Yes |
| `@zuccadev-labs/zuix-zicon` | [`zicon/`](./zicon/README.md) | 346 icons in `outline` and `solid`, a `<z-icon>` element and a React component | Yes |
| `@zuccadev-labs/zuix-zui` | [`zui/`](./zui/README.md) | 124 accessible components that only read tokens | Yes |
| `@zuccadev-labs/zuix-zout` | [`zout/`](./zout/README.md) | 14 layouts: shell, split panes, work tabs, grids | Yes |
| `@zuccadev-labs/zuix-zudocs` | `zudocs/` | Documentation standard and Docusaurus template | No |

The five published packages share one version number and are installed and upgraded together.

## Install

```
pnpm add @zuccadev-labs/zuix                 # the whole suite
pnpm add react react-dom                     # only for the React binding
```

Or package by package: `pnpm add @zuccadev-labs/zuix-zui @zuccadev-labs/zuix-zicon @zuccadev-labs/zuix-tokens`
(plus `@zuccadev-labs/zuix-zout` for layouts). `@zuccadev-labs/zuix-zicon` is a peer of `zui` and `zout`:
the application always installs it. `zui` has a single runtime dependency, `@zuccadev-labs/zuix-tokens`.

## Quick start

### Plain HTML

In a checkout of this repository, `pnpm dist` generates the files ready to link:

```html
<html data-theme="dark" data-brand="dazlabs">
<head>
  <link rel="stylesheet" href="tokens/dist/tokens.css">
  <link rel="stylesheet" href="zui/dist/zui.css">
  <link rel="stylesheet" href="zout/dist/zout.css">
</head>
<body class="z-root z-canvas" data-z-dom>
  <button type="button" class="z-btn z-btn--primary" data-size="md">
    <z-icon name="plus" size="16"></z-icon>
    New project
  </button>

  <script type="module">
    import "./zicon/dist/zicon.element.js";          // defines <z-icon>
    import { init } from "./zui/dist/zui.dom.js";    // behavior
    init();
  </script>
</body>
</html>
```

The full example, with every component, is `examples/html/index.html`.

With a bundler (Vue, Svelte, Angular, Astro) the same pieces come from the packages:

```js
import "@zuccadev-labs/zuix-tokens/tokens.css";
import "@zuccadev-labs/zuix-zui/styles.css";
import "@zuccadev-labs/zuix-zout/styles.css";
import "@zuccadev-labs/zuix-zicon/element";
import { init } from "@zuccadev-labs/zuix-zui/dom";

init();
```

### React

```tsx
import "@zuccadev-labs/zuix-tokens/tokens.css";   // or @zuccadev-labs/zuix-tokens/css/<brand>.css
import "@zuccadev-labs/zuix-zui/styles.css";
import "@zuccadev-labs/zuix-zout/styles.css";
import "@zuccadev-labs/zuix-zicon/all";           // registers the icons

import { Button } from "@zuccadev-labs/zuix-zui";

<Button variant="primary" icon="plus">New project</Button>
```

With the umbrella package, the same pieces come from one dependency:

```tsx
import "@zuccadev-labs/zuix/styles.css";          // tokens + components + layouts
import "@zuccadev-labs/zuix/zicon/all";           // registers the icons
import { Button } from "@zuccadev-labs/zuix/zui";
import { Stack } from "@zuccadev-labs/zuix/zout";
```

The theme is chosen with `data-theme="dark"` or `"light"` on `<html>`; the brand, by importing its CSS or
with `data-brand`. The binding requires React 19; React 18 is not supported.

## What you can rely on

| Area | State |
|---|---|
| Accessibility | WCAG 2.2 AA is measured, not assumed: the token build checks every text and surface pair the stylesheets actually use (4.5:1) and non-text contrast (3:1). `forced-colors`, `prefers-contrast`, `prefers-reduced-motion` and `prefers-reduced-transparency` are handled, right-to-left works through logical properties, and touch targets grow to 40 px with a coarse pointer |
| Browsers | Chrome and Edge 116, Firefox 125, Safari 17, iOS Safari 18.3. The Popover API sets the floor |
| Runtime | Node 22.12 or later for the packages; React 19 and React DOM 19 as optional peers |
| Security | Framework-free code writes text with `textContent`, works under Trusted Types and a strict Content Security Policy, and `<z-icon>` never uses `innerHTML`. Releases are published from CI with npm trusted publishing and provenance |

Details, limits and what I have not been able to test (real Safari, real touch devices, screen readers) are in
[Accessibility](./docs/users/09-accesibilidad.md) and [Compatibility](./docs/users/10-compatibilidad.md).

## Development

Requirements: Node 22.12 or later (I develop, run CI and publish on Node 26) and pnpm 12. `packageManager`
pins the exact pnpm version; `corepack enable` installs it.

```
pnpm install
pnpm check                                        # tokens, icons, style audit, manifests, HTML contract, types
pnpm --filter @zuccadev-labs/zuix-zudocs start    # documentation site with the live catalog
```

| Command | What it does |
|---|---|
| `pnpm check` | Regenerates and validates tokens, icons, manifests and the HTML contract; audits styles; type-checks |
| `pnpm --filter @zuccadev-labs/zuix-zudocs build` | Builds the documentation site and fails on broken links or anchors |
| `pnpm lint` | Biome (TypeScript, React, accessibility, CSS and JSON) plus the `"use client"` rule |
| `pnpm format` / `pnpm format:check` | Applies or checks formatting |
| `pnpm test:unit` | Unit tests of the pure logic with a coverage threshold (`node:test`) |
| `pnpm test:html` | HTML contract and `@zuccadev-labs/zuix-zui/dom` in a browser, without React |
| `pnpm test:browser` | The React example application in a browser |
| `pnpm test:site` | The built documentation site: links, console, accessibility |
| `pnpm build` | Generates the publishable `dist/` of `zicon`, `zui` and `zout` and checks the umbrella |
| `pnpm test:pack` | Packs the five packages and consumes them outside the workspace |
| `pnpm verify` | All of the above in order, in Chromium. The gate before a release |
| `pnpm bump check` | Checks the single version and the `CHANGELOG.md` entries |

Browser suites use the Chrome installed on the system. For Firefox and WebKit: `pnpm test:html:all`,
`pnpm test:browser:all` and `pnpm test:site:all`.

## Status

The suite is on npm under the `@zuccadev-labs` organization
([`@zuccadev-labs/zuix`](https://www.npmjs.com/package/@zuccadev-labs/zuix)). `0.2.0` breaks with `0.1.0`:
it drops the third-party UI library the React binding was built on, moves dialogs to the native `<dialog>`
and raises the minimum Node version. While the version is `0.x`, a `MINOR` bump may break
([Versioning](./docs/package/01-versionado.md)). Releases are published automatically when a version bump
reaches `main` ([Publishing](./docs/package/02-publicacion.md)).
